# features

Проверки окружения для мониторинга. Каждая фича реализует общий интерфейс:

```kotlin
interface DataFeature<out T> { suspend fun getData(): T? }                                   // данные или null
interface ConditionFeature<in P> { suspend fun isMeetsCondition(input: P): ConditionResult } // проверка условия
```

`ConditionResult` — `True`, `False` или `Unknown(reason)`. Причина `Unknown` всегда из одного общего списка `UnknownReason`.

## Фичи

| Фича | Вход `isMeetsCondition` | `getData` | Время |
|---|---|---|---|
| `WifiNetworksFeature` | имена сетей (SSID) | сети из системного кеша | мгновенно, скан не запускает |
| `BluetoothConnectedDevicesFeature` | имена устройств | подключённые сейчас устройства | до 2 сек на профиль |
| `NearbyBluetoothDevicesFeature` | имена устройств | BLE-устройства рядом | скан до 10 сек, не чаще раза в 30 сек |
| `LocationFeature` | список `GeoZone` (точка + радиус) | нет | до 20 сек |

Во всех фичах условие выполняется, если подходит **хотя бы одно** значение из входного списка. Пустой список даёт `False`.

## Причины `Unknown`

| `UnknownReason` | Когда | Фичи |
|---|---|---|
| `PERMISSION_DENIED` | не выдано runtime-разрешение | все |
| `SOURCE_DISABLED` | выключен Bluetooth или геолокация | Bluetooth, Location |
| `SOURCE_UNAVAILABLE` | на устройстве нет нужного железа или сервиса | все |
| `TOO_FREQUENT` | предыдущий скан запущен меньше 30 сек назад | Nearby Bluetooth |
| `READ_FAILED` | система вернула ошибку скана | Nearby Bluetooth |
| `NO_DATA` | данных нет: кеш Wi-Fi пуст, за 20 сек не пришло ни одной координаты | Wi-Fi, Location |
| `MOCK_DATA` | пришли только поддельные координаты (`isMock`) | Location |
| `NOT_ACCURATE_ENOUGH` | пользователь у границы зоны, погрешность не даёт решить | Location |
| `SOURCES_CONFLICT` | GPS и сеть показывают разные места, возможна подмена GPS | Location |
| `NOT_VERIFIED` | ответил только GPS, сверить не с чем | Location |

## LocationFeature

Одновременно слушает два независимых источника координат:

* **GPS** — спутники. Точный, но его можно заглушить или подменить.
* **Сеть** — местоположение по видимым Wi-Fi-точкам и сотовым вышкам. Грубее, глушилки GPS на него не действуют.

У каждой координаты есть погрешность. Android отдаёт её с уверенностью около 68%, поэтому мы умножаем её на 2 и получаем около 95%. Дальше `a` — это уже удвоенная погрешность. Для зоны с радиусом `r` и расстоянием до центра `d`:

* `d + a ≤ r` — точно внутри;
* `d − a > r` — точно снаружи;
* иначе — неясно.

Порядок проверки:

1. Зон нет → `False`. Нет разрешения → `PERMISSION_DENIED`. Геолокация выключена → `SOURCE_DISABLED`.
2. Ждём координаты до 20 сек. Поддельные и старше 10 сек пропускаем.
3. Когда есть координаты от обоих источников, сверяем их. Они расходятся, если расстояние между ними больше суммы их погрешностей плюс путь, который пользователь мог проехать между двумя замерами (до 30 м/с, около 108 км/ч):
   * расходятся 3 раза подряд → `SOURCES_CONFLICT`, стоп;
   * расходятся, но реже → ждём следующий замер, первая точка GPS бывает плохой;
   * не расходятся и хотя бы одна точно внутри зоны или точно снаружи → `True` / `False`, стоп.
4. Прошло 20 сек без уверенного ответа:
   * последние координаты расходятся → `SOURCES_CONFLICT`;
   * есть обе, но обе «неясно» → `NOT_ACCURATE_ENOUGH`;
   * есть только сеть → её ответ, если он точный, иначе `NOT_ACCURATE_ENOUGH`;
   * есть только GPS → `NOT_VERIFIED`;
   * были только поддельные → `MOCK_DATA`;
   * ничего → `NO_DATA`.

Правила лежат в `LocationJudge` (чистый Kotlin) и покрыты тестами `LocationJudgeTest`.

В фоне фиче нужен foreground service типа `location`.
