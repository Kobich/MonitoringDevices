# Файловый менеджер

Статья описывает три модуля, которые вместе дают работу с файлами в приложении:

- **`:features:file-manager`** — основной модуль, файловый менеджер. Хранит файлы приложения, позволяет импортировать их с устройства, экспортировать обратно, создавать папки, удалять и открывать файлы на просмотр.
- **`:features:document-viewer`** — экран просмотра. Показывает открытый файл: страницы PDF, текст, картинку, офисный документ; аудио и видео проигрывает своим плеером.
- **`:core:document`** — чтение файлов. Определяет тип файла и готовит его к показу. Состоит из `api` (что можно получить из файла) и `impl` (как это делается).

## Кто что делает

Менеджер файлы не открывает. По нажатию на файл он вызывает `onFileOpen(file)`, а приложение (`:app`) открывает по этому файлу просмотрщик. Модули друг от друга не зависят: связывает их только приложение, поэтому просмотрщик можно открыть и для файла не из менеджера.

Просмотрщик передаёт файл в `:core:document`. Тот определяет тип по расширению и возвращает документ одного из шести видов. Дальше работа делится по-разному в зависимости от вида:

```
:features:file-manager ── onFileOpen(file) ──▶ :app ──▶ :features:document-viewer
                                                                │
                                                     DocumentReader.read(file)
                                                                ▼
                                                        :core:document
                                                                │
        ┌───────────────────────────┬───────────────────────────┼───────────────────────────┐
        ▼                           ▼                           ▼                           ▼
   PDF, картинка, текст        офисный документ,            аудио                      видео
   core:document рисует        Markdown, SVG               core:document читает       core:document проверяет
   страницы, декодирует        core:document делает HTML   теги и обложку             дорожки (без видео —
   картинку, подбирает         (офис и Markdown —                                     открывает как аудио)
   кодировку                   через OpenDocument.core)          │                           │
        │                            │                           │                           │
        ▼                            ▼                           ▼                           ▼
   просмотрщик показывает      просмотрщик показывает      просмотрщик играет          просмотрщик играет
   готовое                     в WebView                   плеером Media3              плеером Media3
```

То есть через `:core:document` проходит любой файл, включая mp4. Но для аудио и видео он только узнаёт, что это за файл, и достаёт метаданные; проигрывает их плеер Media3 внутри просмотрщика.

## Хранилище

Файлы менеджера лежат во внутренней памяти приложения, в папке `filesDir/storage`. Другие приложения и проводник телефона туда не видят, поэтому разрешений на доступ к памяти не нужно. Снаружи файлы приходят и уходят только через системные окна выбора файла (Storage Access Framework).

Отдельная папка `storage`, а не сам `filesDir`, потому что в `filesDir` пишут служебные файлы библиотеки (например, `profileInstalled` от androidx.profileinstaller).

Резервное копирование выключено: файлы не уходят в облачный бэкап Google и не переносятся на новый телефон. При удалении приложения они удаляются.

## Возможности менеджера

**Навигация.** Менеджер открывается на корне хранилища, сверху — цепочка папок для возврата на любой уровень. Сначала идут папки, потом файлы, внутри групп — по имени без учёта регистра. «Назад» поднимается на папку вверх, в корне закрывает менеджер.

**Выбор.** Долгое нажатие включает режим выбора: нажатия выделяют элементы, в верхней панели появляются удаление, «выбрать все» и экспорт. «Назад» сначала выключает режим выбора.

**Импорт.** Файлы (можно несколько сразу) или папка целиком копируются в открытую папку. Занятое имя получает номер: `отчёт (1).pdf`. Если импорт папки оборвался, скопированная часть удаляется; при импорте нескольких файлов уже скопированные до ошибки остаются.

**Экспорт.** Один файл — через окно «Сохранить как», папка или несколько элементов — в выбранную папку на устройстве. При обрыве уже скопированное удаляется.

**Новая папка.** Имя не пустое, не `.` и не `..`, без `/`, `\` и управляющих символов, до 255 байт в UTF-8, не совпадает с существующим. При ошибке диалог остаётся открытым и пишет причину.

**Удаление** — после подтверждения, папка удаляется со всем содержимым. Несколько элементов удаляются по одному, удаление останавливается на первой ошибке.

Операции выполняются по одной. Если Android выгрузит приложение, пока пользователь выбирает файл в системном окне, после возвращения менеджер откроется на той же папке и доделает импорт или экспорт.

## Форматы

Тип определяется по расширению, не по содержимому. Файл `отчёт.pdf` с чужим содержимым откроется с ошибкой «повреждён».

| Что | Расширения | Как показывается |
|---|---|---|
| PDF | pdf | страницы списком под ширину экрана, каждая рисуется, когда до неё доходит прокрутка |
| Текстовые документы | docx, doc, odt, rtf, pages | страницами, как в оригинале, страница вписана в ширину экрана |
| Таблицы | xlsx, xls, ods, csv, numbers | в натуральную величину с прокруткой, вкладка на каждый лист |
| Презентации и рисунки | pptx, ppt, odp, key, odg | слайды вписаны в ширину экрана |
| Markdown | md, markdown | оформленный текст по ширине экрана |
| Текст | txt, log, json, xml | построчно, сверху кодировка и число строк; кодировка определяется сама (UTF-8, UTF-16, Windows-1251, Latin-1) |
| Картинки | png, jpg, jpeg, gif, webp, bmp, heic, heif, svg | с увеличением жестом и двойным нажатием; GIF и WebP анимируются |
| Аудио | mp3, wav, m4a, aac, ogg, oga, opus, flac | обложка, название, исполнитель, плеер с перемоткой |
| Видео | mp4, m4v, mov, 3gp, webm, mkv | плеер с кнопками управления; файл без видеодорожки открывается как аудио |

Остальные расширения не поддерживаются.

Плеер живёт во ViewModel просмотрщика: при повороте экрана воспроизведение продолжается, при уходе приложения в фон встаёт на паузу.

В верхней панели просмотрщика есть кнопка «Открыть в другом приложении»: исходный файл уходит в системный выбор приложений, например в Word, чтобы сравнить отображение.

## Офисные документы

Офисные файлы и Markdown `:core:document` переводит в HTML с помощью библиотеки OpenDocument.core (MPL-2.0), просмотрщик показывает результат в WebView. SVG тоже показывается в WebView, но без библиотеки: картинка вставляется в HTML-страницу через `<img>`, поэтому её скрипты не выполняются. WebView не ходит в сеть и видит только папку с результатом конвертации.

Результат конвертации хранится в кэше `cacheDir/documents` (до 200 MB): повторно файл открывается сразу, изменённый файл конвертируется заново, при переполнении первыми удаляются давно не открытые.

Библиотека показывает Word не во всём как Word, поэтому `:core:document` правит копию файла перед конвертацией и результат после неё:

- диаграммы docx и pptx рисует картинками того же размера (столбцы, линейчатые, линии, области, круговые, кольцевые, точечные);
- слово длиннее строки, в том числе текст с неразрывными пробелами, переносит посреди слова, как Word, в том числе в ячейках таблиц;
- восстанавливает отступ первой строки («красную строку») и выступ абзацев в docx.

Если правка не удалась, документ открывается без неё.

## Ограничения

- **Версии Android.** Модули работают с Android 6 (API 23); текущее приложение-хост требует Android 16 из-за модулей сканера. Офисные документы — с Android 8 (API 26), это требование OpenDocument.core; ниже они не открываются, а Markdown показывается обычным текстом. HEIF и анимация GIF/WebP — с Android 9; ниже HEIF не открывается, у анимации показывается первый кадр.
- **Файлы с паролем** не открываются («тип не поддерживается»), ввода пароля нет.
- **Шрифты.** Шрифтов Word на телефоне нет, их заменяют системные: текст может занимать чуть другое место. Символьные шрифты (Wingdings и подобные) показываются буквами вместо значков.
- **Фигуры Word** (стрелки, треугольники и т.п.) не отображаются, на их месте пусто. Прямоугольники отображаются.
- **Диаграммы в xlsx** не рисуются.
- **Красная строка** восстанавливается только в docx; в odt её показывает сама библиотека, в rtf она теряется. Нужен WebView на Chromium 105+, на более старом отступа нет.
- **Файлы, сохранённые в WordPad**, могут отображаться сломанными: WordPad поддерживает только часть формата docx и переписывает файл при сохранении.
- **Объём.** Текст показывается до 1 000 000 символов, дальше обрезается с пометкой. Если на картинку или страницу не хватает памяти — ошибка «слишком большой».

## Ошибки

Просмотрщик показывает причину и кнопку «Retry».

| Причина | Сообщение | Когда |
|---|---|---|
| Не найден | File not found | файл удалён или перемещён |
| Не поддерживается | This file type isn't supported | неизвестное расширение, нужна более новая версия Android, файл с паролем |
| Повреждён | The file is damaged or has an unknown structure | содержимое не соответствует расширению или испорчено |
| Слишком большой | The file is too large | не хватило памяти |
| Ошибка чтения | Can't read the file | файл не прочитался |

Ошибки менеджера показываются внизу экрана с причиной: «Import failed», «Export failed», «Delete failed», «Can't create folder». Если на телефоне нет приложения для выбора файлов — «No app available to pick a document».

Тексты интерфейса пока только на английском.

## Логи

В логгер действий (`ActionLogger`, `:core:logger:client:api`) пишутся только основные действия пользователя, без имён файлов и папок:

| Экран | `elementId` | Действие |
|---|---|---|
| `file_manager` | `open_file` | открыл файл |
| `file_manager` | `import_files`, `import_folder` | начал импорт файлов или папки |
| `file_manager` | `export` | начал экспорт выделенного |
| `file_manager` | `delete_confirm` | подтвердил удаление |
| `file_manager` | `create_folder_confirm` | подтвердил создание папки |
| `document_viewer` | `open_in_other_app` | открыл файл в другом приложении |
| `document_viewer` | `retry` | повторил открытие после ошибки |

Сейчас подключена затычка логгера: события идут только в Logcat. Настоящий клиент ставится вместо неё без изменений в коде.

Отладочные записи в Logcat:

```
adb logcat -s FileManager FileStorage DocumentViewer DocumentReader Player OdrHtmlConverter OfficeReader RenderCache ActionLogger
```

## Подключение

```kotlin
// settings.gradle.kts
include(":core:common-ui")
include(":core:document:api")
include(":core:document:impl")
include(":core:logger:client:api")
include(":features:file-manager")
include(":features:document-viewer")

// build.gradle.kts приложения
implementation(project(":features:file-manager"))
implementation(project(":features:document-viewer"))
implementation(project(":core:document:impl"))
```

Нужен Hilt: `@HiltAndroidApp` на `Application`, `@AndroidEntryPoint` на Activity. `DocumentReader` для просмотрщика создаётся один на приложение: все чтения делят кэш и очередь конвертации.

```kotlin
@Module
@InstallIn(SingletonComponent::class)
object DocumentCoreModule {
    @Provides
    @Singleton
    fun provideDocumentReader(@ApplicationContext context: Context): DocumentReader = DocumentCore(context).reader
}
```

Связка экранов в навигации:

```kotlin
@AndroidEntryPoint
class MainActivity : ComponentActivity() {
    @Inject lateinit var fileManager: FileManagerFeatureApi
    @Inject lateinit var documentViewer: DocumentViewerFeatureApi
    // ...
}

NavHost(navController = navController, startDestination = "file_manager") {
    composable("file_manager") {
        fileManager.FileManagerScreen(
            modifier = Modifier,
            onBackClick = { finish() },
            onFileOpen = { file -> navController.navigate("file_viewer?path=${Uri.encode(file.absolutePath)}") }
        )
    }
    composable(
        route = "file_viewer?path={path}",
        arguments = listOf(navArgument("path") { type = NavType.StringType })
    ) { entry ->
        documentViewer.DocumentViewerScreen(
            file = File(entry.arguments?.getString("path").orEmpty()),
            modifier = Modifier,
            onBackClick = { navController.popBackStack() }
        )
    }
}
```

Для показа файла без менеджера достаточно `:features:document-viewer` и `:core:document:impl`.

## Проверка

Пока приложение в разработке, при первом запуске в хранилище кладутся примеры: docx с таблицей, картинками и диаграммами, csv, md, pdf, png, wav, тексты в UTF-8 и Windows-1251. Перед релизом генератор (пакет `sample` в `:app`) удаляется.

Тесты без устройства:

```bash
./gradlew :core:document:impl:testDebugUnitTest :features:file-manager:testDebugUnitTest
```

Покрыты определение кодировки текста, восстановление красной строки, защита хранилища от выхода за его пределы (`..`, символические ссылки) и правила имён файлов.
