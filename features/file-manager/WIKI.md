# Файловый менеджер и просмотр документов

Статья описывает, как в приложении устроена работа с файлами: где они хранятся, что пользователь может с ними делать и как файл попадает на экран просмотра. Она для разработчиков, которые будут подключать или дорабатывать эти модули, для аналитиков и для тех, кто пишет пользовательскую документацию. Подробности по каждому модулю — в его `README.md`.

## Из чего это состоит

Работа с файлами разложена на три модуля и приложение, которое их связывает.

- **`:features:file-manager`** — файловый менеджер. Показывает папки и файлы приложения, умеет импортировать файлы с устройства, экспортировать их обратно, создавать папки и удалять. Открывать файлы он не умеет: когда пользователь нажимает на файл, менеджер отдаёт его наружу.
- **`:features:document-viewer`** — экран просмотра. Получает файл и показывает его: страницы PDF, текст, картинку, плеер для аудио и видео, офисный документ.
- **`:core:document`** — чтение файлов. Разбит на две части: `api` описывает, что можно получить из файла, а `impl` это делает. Просмотрщик зависит только от `api` и не знает, как устроено чтение внутри.
- **`:app`** — приложение. Оно ставит менеджер и просмотрщик на один экранный маршрут: файл, выбранный в менеджере, открывается в просмотрщике.

Модули друг о друге не знают. Менеджер не зависит от просмотрщика, просмотрщик не зависит от менеджера. Поэтому любой из них можно подключить отдельно: например, показать просмотрщиком файл, скачанный из сети.

```
Пользователь нажал на файл
        │
        ▼
:features:file-manager ── onFileOpen(file) ──▶ :app (навигация)
                                                  │
                                                  ▼
                                   :features:document-viewer
                                                  │ DocumentReader.read(file)
                                                  ▼
                                   :core:document:impl ── Document ──▶ экран просмотра
```

## Где лежат файлы

Все файлы менеджера хранятся во внутренней памяти приложения, в папке `storage` внутри `filesDir`. Отдельная папка нужна потому, что в `filesDir` свои служебные файлы кладут и библиотеки, и пользователю их видеть незачем.

Эта память доступна только самому приложению. Другие приложения и сам пользователь через проводник телефона в неё не попадают, поэтому менеджеру не нужны разрешения на доступ к памяти. Файлы приходят снаружи и уходят наружу только через системные окна выбора файла (Storage Access Framework), где пользователь сам решает, что отдать и куда сохранить.

Резервное копирование выключено: файлы не попадают в облачный бэкап Google и не переносятся на новый телефон. Если приложение удалить, файлы удалятся вместе с ним.

## Что умеет файловый менеджер

Менеджер открывается на корне хранилища. Сверху цепочка папок, по ней можно вернуться на любой уровень. В списке сначала идут папки, потом файлы, внутри каждой группы — по имени без учёта регистра.

Нажатие на папку открывает её, нажатие на файл открывает его в просмотрщике. Долгое нажатие включает режим выбора: в нём нажатия выделяют элементы, а в верхней панели появляются удаление и меню с выбором всех и экспортом. Кнопка «Назад» сначала выходит из режима выбора, потом поднимается на папку вверх, а в корне закрывает менеджер.

**Импорт.** В меню верхней панели есть импорт файлов (можно выбрать сразу несколько) и импорт папки целиком, со всем содержимым. Всё копируется в открытую сейчас папку. Если имя уже занято, к новому добавляется номер: `отчёт (1).pdf`, `отчёт (2).pdf`. Если импорт папки оборвался на середине, скопированная часть удаляется. При импорте нескольких файлов те, что успели скопироваться до ошибки, остаются.

**Экспорт.** Один файл экспортируется через окно «Сохранить как». Папка или несколько элементов — через выбор папки на устройстве, куда всё копируется. Если экспорт оборвался на середине, уже скопированное удаляется, чтобы снаружи не осталось половины.

**Новая папка.** Имя не может быть пустым, не может быть `.` или `..`, не может содержать `/`, `\` и управляющие символы, должно укладываться в 255 байт в UTF-8 и не должно совпадать с уже существующим именем. При ошибке диалог остаётся открытым и объясняет, что не так.

**Удаление** идёт после подтверждения. Папка удаляется со всем содержимым. Если выбрано несколько элементов, они удаляются по одному и удаление останавливается на первой ошибке.

Операции выполняются по одной. Пока идёт одна, другую начать нельзя, а после каждой список перечитывается. Если Android выгрузит приложение, пока пользователь выбирает файл в системном окне, менеджер после возвращения откроется на той же папке и закончит начатый импорт или экспорт.

## Как файл попадает на экран

Когда пользователь нажимает на файл, менеджер вызывает `onFileOpen(file)` и больше ничего не делает. Приложение переходит на маршрут просмотрщика и передаёт ему путь к файлу.

Просмотрщик создаёт для файла свою ViewModel и просит `DocumentReader` прочитать его. Тип файла определяется по расширению, а не по содержимому: `отчёт.pdf` читается как PDF, даже если внутри что-то другое (тогда пользователь увидит ошибку «повреждён»). По расширению выбирается нужный «читатель», и он возвращает документ одного из шести видов: PDF, HTML, текст, картинка, аудио или видео. Под каждый вид у просмотрщика свой экран.

Тяжёлая работа — конвертация, декодирование картинок, отрисовка страниц PDF — идёт не на главном потоке. Пока документ открывается, на экране индикатор загрузки. Документ закрывается, когда пользователь уходит с экрана. ViewModel переживает поворот экрана, поэтому видео и аудио при повороте продолжают играть, а при уходе приложения в фон встают на паузу.

## Какие файлы открываются

| Что | Расширения | Как показывается |
|---|---|---|
| PDF | pdf | страницы списком, каждая рисуется под ширину экрана, когда до неё доходит прокрутка |
| Word и другие текстовые документы | docx, doc, odt, rtf, pages | страницами, как в оригинале, страница вписана в ширину экрана |
| Таблицы | xlsx, xls, ods, csv, numbers | в натуральную величину с прокруткой, у каждого листа своя вкладка |
| Презентации и рисунки | pptx, ppt, odp, key, odg | слайды вписаны в ширину экрана |
| Markdown | md, markdown | оформленный текст по ширине экрана |
| Текст | txt, log, json, xml | построчно, сверху кодировка и число строк |
| Картинки | png, jpg, jpeg, gif, webp, bmp, heic, heif, svg | с увеличением жестом и двойным нажатием, GIF и WebP анимируются |
| Аудио | mp3, wav, m4a, aac, ogg, oga, opus, flac | обложка, название, исполнитель, плеер с перемоткой |
| Видео | mp4, m4v, mov, 3gp, webm, mkv | плеер с кнопками управления; файл без видеодорожки открывается как аудио |

Остальные расширения не поддерживаются, и пользователь увидит «This file type isn't supported».

Кодировку текста определять не нужно: просмотрщик сам различает UTF-8, UTF-16, Windows-1251 и Latin-1. Старые русские тексты в Windows-1251 открываются нормально.

Справа в верхней панели просмотрщика есть кнопка «Открыть в другом приложении». Она отдаёт исходный файл системному выбору приложений, например Word или WPS. Это удобно, чтобы сравнить, как документ выглядит у нас и в «родной» программе.

## Как показываются офисные документы

Офисные файлы Android сам не читает. Их переводит в HTML библиотека OpenDocument.core (лицензия MPL-2.0), а просмотрщик показывает результат во встроенном браузере. Браузер не ходит в сеть и не видит других файлов: ему доступна только папка с результатом конвертации.

Конвертация занимает время, поэтому результат сохраняется в кэше (`cacheDir/documents`, до 200 MB). Повторно тот же файл открывается сразу. Если файл изменился, он конвертируется заново. Когда кэш переполняется, первыми удаляются документы, которые давно не открывали.

OpenDocument.core показывает Word не во всём так, как Word, поэтому перед конвертацией приложение правит копию файла, а после конвертации — результат:

- диаграммы в docx и pptx библиотека не рисует, поэтому приложение само рисует их картинками того же размера: столбцы, линейчатые, линии, области, круговые, кольцевые и точечные;
- слово длиннее строки, в том числе предложение, склеенное неразрывными пробелами, переносится посреди слова, как в Word, а не вылезает за страницу; в ячейках таблиц тоже;
- отступ первой строки («красная строка») и выступ абзацев в docx библиотека теряет, приложение их восстанавливает.

Если какая-то правка не удалась, документ всё равно откроется, просто без неё.

## Ограничения

Об этом стоит знать заранее, чтобы не искать ошибку там, где её нет.

- **Версии Android.** Менеджер, просмотрщик и чтение документов работают с Android 6 (API 23). Текущее приложение-хост требует Android 16, но только из-за модулей сканера, к файлам это не относится. Офисные документы открываются с Android 8 (API 26): этого требует OpenDocument.core. На Android 6–7 офисные файлы не поддерживаются, а Markdown показывается обычным текстом. HEIF и анимация GIF и WebP требуют Android 9; ниже HEIF не открывается, а у анимации показывается первый кадр.
- **Файлы с паролем** не открываются, пользователь увидит «тип не поддерживается». Ввода пароля в приложении нет.
- **Шрифты.** На телефоне нет шрифтов Word (Calibri, Arial Black и других), их заменяют системные. Текст может занять немного другое место, а символьные шрифты вроде Wingdings показываются обычными буквами вместо значков.
- **Фигуры Word.** Нарисованные в Word фигуры (стрелки, треугольники и прочее) не отображаются, на их месте пустое место. Прямоугольники показываются.
- **Диаграммы в таблицах xlsx** не рисуются. В docx и pptx рисуются.
- **Красная строка** восстанавливается только в docx. В rtf она теряется, в odt её показывает сама библиотека. Для красной строки нужен встроенный браузер Chromium 105 или новее; он обновляется через Play, на старом отступа просто не будет.
- **Файлы, сохранённые в WordPad**, могут выглядеть сломанными. WordPad понимает только часть формата docx и при сохранении переписывает файл по-своему. Word такие файлы прощает, наша библиотека показывает то, что в них записано. Документы стоит готовить в Word, LibreOffice или Google Docs.
- **Большие файлы.** Текст показывается до миллиона символов, дальше обрезается, и об этом написано над текстом. Если для картинки или страницы не хватает памяти, пользователь увидит «файл слишком большой».

## Ошибки, которые видит пользователь

Просмотрщик объясняет, почему файл не открылся, и предлагает попробовать ещё раз.

| Причина | Сообщение | Когда бывает |
|---|---|---|
| Не найден | File not found | файл удалили или переместили |
| Не поддерживается | This file type isn't supported | неизвестное расширение, нужна более новая версия Android, файл с паролем |
| Повреждён | The file is damaged or has an unknown structure | содержимое не соответствует расширению или файл испорчен |
| Слишком большой | The file is too large | не хватило памяти, например на огромную картинку |
| Ошибка чтения | Can't read the file | файл не удалось прочитать |

Ошибки менеджера показываются внизу экрана: «Import failed», «Export failed», «Delete failed», «Can't create folder» с причиной. Если на телефоне нет приложения для выбора файлов, менеджер так и скажет: «No app available to pick a document».

Все тексты интерфейса сейчас на английском.

## Логи

Действия пользователя пишутся в логгер действий (`ActionLogger`, модуль `:core:logger:client:api`). Логируются только основные действия, чтобы при разборе не тонуть в лишнем:

| Экран | Событие (`elementId`) | Что сделал пользователь |
|---|---|---|
| `file_manager` | `open_file` | открыл файл |
| `file_manager` | `import_files`, `import_folder` | начал импорт файлов или папки |
| `file_manager` | `export` | начал экспорт выделенного |
| `file_manager` | `delete_confirm` | подтвердил удаление |
| `file_manager` | `create_folder_confirm` | подтвердил создание папки |
| `document_viewer` | `open_in_other_app` | открыл файл в другом приложении |
| `document_viewer` | `retry` | повторил попытку после ошибки |

Имена файлов и папок в лог не попадают, это данные пользователя. Сейчас в проекте стоит затычка логгера, которая пишет события только в Logcat; настоящий клиент подключается вместо неё без изменений в коде.

Для отладки в Logcat есть подробные записи по тегам:

```
adb logcat -s FileManager FileStorage DocumentViewer DocumentReader OdrHtmlConverter OfficeReader RenderCache ActionLogger
```

## Как подключить к приложению

Подключаются четыре модуля: менеджер, просмотрщик и обе части чтения документов (`api` приходит вместе с `impl`).

```kotlin
// settings.gradle.kts
include(":core:common-ui")
include(":core:document:api")
include(":core:document:impl")
include(":core:logger:client:api")
include(":features:file-manager")
include(":features:document-viewer")

// build.gradle.kts приложения
implementation(project(":features:file-manager"))
implementation(project(":features:document-viewer"))
implementation(project(":core:document:impl"))
```

Фичи используют Hilt. Приложению нужны `@HiltAndroidApp` на классе `Application` и `@AndroidEntryPoint` на Activity. Просмотрщику нужен `DocumentReader`: его создают один раз на всё приложение, потому что все чтения делят один кэш и одну очередь конвертации.

```kotlin
@Module
@InstallIn(SingletonComponent::class)
object DocumentCoreModule {
    @Provides
    @Singleton
    fun provideDocumentReader(@ApplicationContext context: Context): DocumentReader = DocumentCore(context).reader
}
```

Остаётся связать экраны навигацией: менеджер отдаёт файл, приложение открывает по нему просмотрщик.

```kotlin
@AndroidEntryPoint
class MainActivity : ComponentActivity() {
    @Inject lateinit var fileManager: FileManagerFeatureApi
    @Inject lateinit var documentViewer: DocumentViewerFeatureApi
    // ...
}

NavHost(navController = navController, startDestination = "file_manager") {
    composable("file_manager") {
        fileManager.FileManagerScreen(
            modifier = Modifier,
            onBackClick = { finish() },
            onFileOpen = { file -> navController.navigate("file_viewer?path=${Uri.encode(file.absolutePath)}") }
        )
    }
    composable(
        route = "file_viewer?path={path}",
        arguments = listOf(navArgument("path") { type = NavType.StringType })
    ) { entry ->
        documentViewer.DocumentViewerScreen(
            file = File(entry.arguments?.getString("path").orEmpty()),
            modifier = Modifier,
            onBackClick = { navController.popBackStack() }
        )
    }
}
```

Если файл нужно показать без менеджера, достаточно просмотрщика и `:core:document:impl`: в `DocumentViewerScreen` можно передать любой файл, который приложение может прочитать.

## Как проверить

Пока приложение в разработке, оно при первом запуске кладёт в хранилище примеры: документ Word с таблицей, картинками и диаграммами, таблицы csv, Markdown, PDF, картинку, звук и тексты в UTF-8 и Windows-1251. Этого хватает, чтобы пройти все виды просмотра. Перед релизом генератор примеров нужно удалить (пакет `sample` в `:app`).

Документ, который выглядит не так, удобно сравнить с другим приложением кнопкой «Открыть в другом приложении».

Часть логики покрыта тестами, которые запускаются без телефона:

```bash
./gradlew :core:document:impl:testDebugUnitTest :features:file-manager:testDebugUnitTest
```

Они проверяют определение кодировки текста, восстановление красной строки, защиту хранилища от выхода за его пределы (через `..` и символические ссылки) и правила имён файлов.
